# Master Data Architecture

Master data records are controlled reference objects used by transaction domains. They have business
keys, technical identifiers, lifecycle rules, audit requirements, and ownership boundaries.

## General Master-Data Rules

- Technical identifiers are immutable and never reused.
- Business keys are human-meaningful but still governed.
- Records used by transactions are not hard-deleted.
- Deactivation prevents new use but preserves history.
- Merge requires explicit duplicate-detection evidence and audit trail.
- Import must validate ownership, uniqueness, localization, and sensitive fields.
- Export permissions are separate from read permissions.
