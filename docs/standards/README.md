# Engineering Standards

The documents in this directory are mandatory unless an approved ADR or time-bounded exception says
otherwise.

| Standard                                               | Subject                            |
| ------------------------------------------------------ | ---------------------------------- |
| [`repository-standards.md`](repository-standards.md)   | Repository-wide invariants         |
| [`coding-standards.md`](coding-standards.md)           | Source quality and testing         |
| [`naming-conventions.md`](naming-conventions.md)       | Names across files and ecosystems  |
| [`commit-conventions.md`](commit-conventions.md)       | Conventional Commits               |
| [`branch-strategy.md`](branch-strategy.md)             | Branch lifecycle and merging       |
| [`versioning-policy.md`](versioning-policy.md)         | Releases and compatibility         |
| [`dependency-policy.md`](dependency-policy.md)         | Selection, locking, and upgrades   |
| [`documentation-policy.md`](documentation-policy.md)   | Documentation quality and location |
| [`review-policy.md`](review-policy.md)                 | Review and approval requirements   |
| [`code-ownership.md`](code-ownership.md)               | Ownership responsibilities         |
| [`repository-governance.md`](repository-governance.md) | Decision authority and exceptions  |
| [`directory-ownership.md`](directory-ownership.md)     | Path-to-owner mapping              |
| [`github-labels.md`](github-labels.md)                 | Issue and pull request taxonomy    |

Standards use the words **must**, **should**, and **may** in the normative sense. Violations marked
as temporary must have an owner, expiry date, compensating control, and tracked remediation.
